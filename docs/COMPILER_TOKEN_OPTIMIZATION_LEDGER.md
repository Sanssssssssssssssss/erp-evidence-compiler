# Compiler 优化简记

更新：2026-09-07。

**一次运行参考：制造约 40 万 token。** 执行＋复核实测 38.4 万，规划历史约 2 万；40 万是预算估算，不是所有案例的平均值。

| 最近的执行＋复核 | 用量 | 结果 |
| --- | ---: | --- |
| 制造 | 38.4 万 | 成功，7/7 正确 |
| 采购 | 至少 29.2 万 | 成功，9/9 正确；部分用量缺失 |
| 发票（新版重跑） | 60.1 万 | 提交成功；1 项证据不足被误判 |

以上不含规划，包含缓存输入。新版发票从空证据重跑：Executor 50.34 万、Verifier 9.81 万，其中缓存输入共 49.20 万。

发票的订单材料缺少 fiscal_position_id，Executor/Verifier 却都认定为空、与发票一致。协议已通过，这一项仍应保留材料不足，不能算业务全对或同质量省 token。

**我们改了什么：**

- Verifier 去掉重复合同和证明：首次复核省 **12.9%**；三组对照最终均 27/27 正确。
- Executor 一次绑定多个字段：制造执行阶段省 **21.2%**；单例历史对照，前后均 7/7 正确。
- Verifier 缺字段时允许自己改一次：修复提交失败；尚未证明省 token，采购单例反而增加 **9.1%**。

这些是不同阶段的结果，不能相加成整体节省率。
